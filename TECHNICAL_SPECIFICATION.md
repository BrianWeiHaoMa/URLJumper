## Approach

URLJumper is a Chrome Manifest V3 extension whose whole state is a few keys in the extension's local storage, with the user's document, stored as one string, as the record of truth. The one idea: every surface derives what it shows from the stored document on demand, and every write to the document is a compare-and-replace performed by one writer, the extension's service worker, which re-reads the document, checks the expectation the requesting surface stated, and writes the whole new text once or not at all. Surfaces keep nothing of their own beyond what the user is typing. Nothing is cached, indexed, migrated, or synchronized.

Inside one profile several surfaces (the popup, settings tabs) run at once, each single-threaded; exactly one service worker instance exists at a time and performs its writes one after another. One copy of the extension runs per Chrome profile; profiles share nothing.

## Foundations

- **TypeScript 7**, strict, for all product code, so the request and reply shapes that cross the worker boundary are one set of types compiled into both sides.
- **Chrome 127 or later** (E1); the manifest declares `minimum_chrome_version` "127", so the Web Store neither installs nor updates 2.0 on an older Chrome (S11).
- **React 19** (`react`, `react-dom`) renders the popup and the settings views: a dozen small states with keyboard focus rules, where a declarative view library is lower risk than hand-written DOM updates. It is the only runtime dependency.
- **Vite 8 with `@crxjs/vite-plugin` 3** builds the extension from a TypeScript `defineManifest` config into `dist/`, with a module service worker; **Node 24 LTS** runs it. `npm run package` type-checks, builds, and zips `dist/` into the Web Store upload: the one command L1 requires. Nothing from the 1.x tree is used.
- **Vitest 5** checks the document module as pure functions. **Playwright 1.64** (channel `chromium`, bundled Chromium 156) loads the built extension into a persistent context headlessly for end-to-end checks.
- **Storage:** `chrome.storage.local` only (F3). No session, sync, IndexedDB, or localStorage.
- **Policy:** manifest CSP `extension_pages` = `default-src 'self'`; system font stacks; every asset in the package (N2, G33).

## Composition

**Document module** (shared code imported by every other part; no state, no Chrome API). Owns every rule about the document's text: splitting into lines; classifying each as mapping, blank, heading comment, or unreadable (F4, F14); validation (F4, G8, G14); line formatting (F12); the single-line edits of G12 as splices of the original strings; search groups and order (G1, G2); argument substitution (F9); the use score (G27); the three-way line merge (G18). Shared meanings it fixes: lines are separated by LF or CRLF and numbered from 1, and the text after the last line break is a line, empty when the document ends with a break; "whitespace" is what ECMAScript `\s` matches and names compare after `String.prototype.toLowerCase()`, both as in 1.x; F12's columns count Unicode code points; G1 (c) measures a filled URL's length in UTF-16 code units, as `String.prototype.length` does; F9 is `encodeURIComponent`, with a lone surrogate encoded as U+FFFD instead of throwing (S14); an unreadable line is one F4 calls an error; a line's **exact text** is its content without its line ending; a mapping's **key** is its lowercased name, a line feed, and its URL.

**Service worker** ("the writer"). The only part that writes the keys `mappings`, `usage`, `draft`, and `omnibox`. Owns the operations below, the omnibox keyword (G28), the menu items (F7, G29), the commands (F5), `runtime.onInstalled` (G23 to G25), and jumps (G6, G26). It receives requests from pages over `chrome.runtime.sendMessage` as plain JSON objects whose shapes are declared once, in a module both the worker and the pages import; it performs them one at a time in arrival order and replies once per request:

- *replace*: the new text and the base text the surface loaded (the stored string exactly as read). Applied when the stored text equals the base and the new text has no F4 error; else refused as `changed`, with the stored text, when they differ, or as `invalid` (G17).
- *load example*: applied when the stored document is absent or whitespace-only; else refused as `not-empty`.
- *insert*: name, URL, note (possibly empty), and the target: end of document, or a heading given as the exact text of its lines and how many runs with that text came before it when loaded. *rewrite*, *remove*, *move* (up or down): the anchor line's exact text and its line number when loaded, plus new fields for a rewrite. The worker finds an anchor as the mapping line with that exact text at that number, else as the single mapping line with that exact text, and a heading as the run with that exact text that has as many such runs before it as when loaded (G9). An anchor found zero or several times is `stale`, with the stored text. A name belonging to another line is `name-taken`, with that line's number. A heading no longer found sends the insert to the end of the document and the reply says so (G9).
- *undo*: the inverse of a change. For a change that left a line (an insert, a rewrite, a move): that line's number and exact text, found again as an anchor is, and the act: remove it, restore the former text, or move it back to the line number it had. For a remove: the removed text and its former line number N; the act re-inserts it as line N, or after the last line when the document has fewer than N−1 lines. Applied only when the anchor, where the act has one, is found, and every name the act writes is free of other lines (G13); else `stale` or `name-taken`.
- *jump*: the mapping's name and URL as stored, the argument text or none, the mode (new tab, with the window the user acted in when the sender knows it and whether the tab is made active; or this tab, with the tab id). The worker records the use, then opens the URL with F9 applied through `tabs.create` or `tabs.update`; the reply says opened, or `failed` with Chrome's message.
- *draft set*: text, base, the time of the edit, and the sending view's identifier, random for each Text view opened, with a number the view raises on every *draft set*; the worker stores them as `draft` unless `draft` already holds a newer time, so a late coalesced write never overtakes a newer edit; edits within the same millisecond are equally recent, and the later to arrive is kept. *draft discard*: the identifier and number of the draft being discarded; the worker removes `draft` only if it holds both, so a discard removes exactly the edit it names and never a later one.
- *reset usage*: removes `usage`.
- *remove intent*: the window and time of the `openIntent` record a popup honored; removes the record only while it still names that window and time, so a record written since for another window stays.

Every write of `mappings` carries the recomputed `usage` in the same `set` call, so the two land together or not at all (S1): each mapping whose key was absent before the write (G26's "creation") gets a history of exactly one use at the write's time, replacing any entry under that key, and entries whose key matches no current mapping are dropped (G27). A *jump* records its use only when its key is in the current document. After a *replace* the worker removes `draft` if the draft's text equals the text just stored. Every applied reply carries the line numbers touched and the exact text written or removed, which is what a surface needs for its confirmation and its Undo. `storage-failed` carries Chrome's error message; a request with no reply (the channel threw) is treated by the surface as `storage-failed`.

**Popup** (`popup.html`): search box, chip, list of seven rows, footer, Name form, row editor, upgrade notice, first-run state, and compact settings (the settings views plus *Open in tab*). It reads storage directly and writes only through the worker, except the keys State assigns to surfaces. It learns why it was opened from the key `openIntent`, written by the worker before it calls `chrome.action.openPopup`: the kind (`new-tab`, `this-tab`, `name-page`, `name-link`), the window it is for, for a link its URL and the page's URL and title, and the time written. The popup finds its own tab and window with `tabs.query({active: true, currentWindow: true})`; it honors the record only when it names the popup's own window and was written within the last 10 seconds, and then has the worker remove it (*remove intent*); a record for another window it leaves alone. The worker removes the record when openPopup rejects for any reason but an inactive window (G29). With no record honored, the popup opens in search with New tab (G5). The tab's `url` and `title` are present when Chrome granted activeTab for the invocation (S5), and the Name form says so when they are not.

**Settings views** (List, Text, Preferences): one React implementation hosted twice, inside the popup and as the options page (`options.html`), declared to open in its own tab, which adds Import and Export beside Preferences (G31). The Text view's editor is a native `textarea`, read-only from Save until the worker's reply. The options page accepts the fragment `#view=text&line=N`, opening the Text view with the caret on line N; the popup's *Open in text* uses it.

**What's-new page** (`whats-new.html`): a static page in the package, opened in a tab from the notice (G25), with five items: an exact name now wins over an earlier line that starts with it; `%s` in a URL takes the text typed after the name; Name this page (its shortcut, suggested Alt+Shift+N; the right-click menu; the Name row); the keyword `j`; Smart order, off for upgraded users, in Preferences.

**Chrome** (external). Provides the stored keys, the popup bubble, the keyword, menus, commands, tabs, clipboard, and downloads. The manifest declares: `name` "URLJumper", `version` "2.0.0", `minimum_chrome_version` "127"; `permissions` exactly `storage`, `activeTab`, `clipboardWrite`, `contextMenus` (the stray `commands` entry of 1.x, which Chrome ignores as unknown, is dropped); `commands` `open-new-tab` (Alt+N), `open-same-tab` (Alt+M), `name-this-page` (Alt+Shift+N), each with `default` and `mac` set to the same key, as 1.x did; `omnibox.keyword` "j"; the CSP above; no `incognito` key (spanning, the default, so one worker serves the profile). Menu items are created in `onInstalled`, and again in `runtime.onStartup` after removing the extension's items, so a Chrome closed before it stored them has them again at its next start: *Name this page in URLJumper* with context `page`, *Name this link in URLJumper* with context `link` (S13). Export is an anchor download of a Blob of the stored text (UTF-8, no byte-order mark added) named `URLJumperMappings.txt`; Import reads the chosen file with `File.text()` (S14). Copying uses `navigator.clipboard.writeText` from the focused page inside the user's click or key handler.

## State

Record of truth: `mappings`, the document as one string (F3). Everything shown about mappings, headings, sections, unreadable lines, and search results is derived from it on each read and again after each `storage.onChanged` (S10); nothing derived is stored.

Other keys, all in `chrome.storage.local`:

- `themePref`: `light` or `dark`; absent means System (F3). Written by Preferences.
- `searchOrder`: `document` or `smart`; absent means Document order. Written `smart` by the worker on `onInstalled` with reason `install`, as its first act (G24), and by Preferences; never written on an update (G23). Absence meaning Document order is the direction that protects upgraders.
- `usage`: an object keyed by mapping key; each value the times of its last ten uses in milliseconds since the Unix epoch, newest last.
- `draft`: the Text view's unsaved text, its base, the time of the edit in milliseconds since the Unix epoch, and the identifier and number of the *draft set* that wrote it. The Text view sends *draft set* after each change, coalescing changes within 300 ms (the loss G19 admits) and while its previous one awaits a reply, and sends any pending one before Save proceeds, so a refused Save leaves the submitted text as the draft unless another view's edit is newer; when its text comes to equal the stored document or the user discards, it cancels any pending *draft set*, waits for the reply to any it sent, and sends *draft discard* with the identifier and number of the draft discarded; a Text view that drops a draft found equal to the stored document names it the same way.
- `omnibox`: the text last typed after the keyword and, for each row of its list, the line number, the mapping's name and URL, and the suffix given, from which, with the typed text, the row's content is rebuilt; the content itself is never stored, since an argument filling many `%s` can make it far larger than the document. Written before each `suggest`; read by `onInputEntered` (G28).
- `upgradeNotice`: `pending`, written by the worker on `onInstalled` with reason `update` and a `previousVersion` below 2.0.0, as its first act; removed by the popup on dismissal.
- `openIntent`: as above; written by the worker, removed by the worker at the request of the popup that honored it or on a final openPopup rejection (G29), ignored when older than 10 seconds.

Budget: `mappings`, `usage` (whose keys repeat every name, which lowercasing can lengthen by half, and every URL, plus up to ten 13-digit times per mapping, at most 1.7 MB for 10,000 mappings), `draft` (text and base), `omnibox` (the typed text and the listed rows' names and URLs, plus at most 0.5 MB of line numbers, suffixes, and structure), and `openIntent` (a link's address with its page's address and title) are at most seven and a half times E3's 1 MB measure plus 2.2 MB, so for any use within E3 the keys together stay under 10.1 MB and S1's 10,485,760-byte quota is never reached. A *draft set* Chrome nevertheless rejects is `storage-failed`: the Text view says the draft is not kept, with the typing still in the textarea.

A change takes effect when Chrome applies the worker's `set`, just before the call resolves, and becomes observable through `onChanged` in every open surface and through the reply; before that point nothing is written. A refused request (`changed`, `stale`, `name-taken`, `not-empty`, `invalid`) writes nothing. A `set` Chrome rejects (over quota, S1) writes nothing of that call; the reply is `storage-failed` and the surface keeps the user's values. A popup closed before the reply (E4) does not stop the worker: the outcome is in storage and shows the next time a surface opens (G21). Chrome exiting during a `set` leaves the key with the old or the new whole value (S1); a `set` not yet started when Chrome exits never happens. Undo state (the inverse operation) lives in the surface's memory alone and dies with it (G15).

## How the guarantees hold

**G1, G2, G28 — one list on two surfaces.** The popup and the worker call the document module's one search function with the same document text, typed text, order preference, and usage, so both lists are the same by construction. Omnibox descriptions show the name and the URL (the filled URL for the argument row), XML-escaped, a character XML 1.0 cannot hold shown as U+FFFD, so no name makes Chrome refuse the list (S7); the default suggestion's description puts a U+2060 WORD JOINER between the `%` and the `s` of each `%s`, so Chrome's substitution of the typed text (S7) leaves its URL as written.

**G4, G6, G26 — nothing opens without Enter or a click; every jump is a use.** The popup sends *jump* only from its Enter handler and its row click handler (R4), awaits the reply, and closes on success; on `failed` it stays and says so. The worker records the use and then navigates, so a navigation of a mapping the document holds was recorded, and a worker that dies between the two steps leaves at most a use without its navigation (S2 makes that remote; the loss is ranking only). The omnibox path calls the same operation. Creation is recorded by key after every write, so a mapping created in the Text view, by *Load example mappings*, or by the Name form counts once. Limit: whether Chrome opens a given scheme, or a URL longer than it navigates to, is E7's.

**G5 — the chip's start mode.** Its only source is `openIntent`: `this-tab` yields This tab; every other kind, and absence, yields New tab.

**G7 — the popup fits.** The root is laid out at a fixed width with header and footer fixed and the current view scrolling between them, at most 600 CSS pixels tall. Chrome clamps the popup's viewport at 600 device-independent pixels (S6), and CSS pixels need not equal those (zoom, scale), so the root also sets its height to `window.innerHeight` whenever the document is taller than the viewport; the footer then stays in view and the view scrolls inside. Chrome sizes the popup to the content in whole device pixels, rounding down, so the root first pads its content up to a whole number of them: at a fractional scale the viewport is then never a fraction of a device pixel short, which would make the view scroll for nothing. By construction.

**G8, G14 — one validation.** The Name form, the row editors, and the worker call the same validation function, and the worker re-validates every *insert* and *rewrite* against the re-read document, so a surface that forgot cannot store a bad line or a duplicate name. An *undo* writes back only a line the document held, which G8 and G14's rules for typed values do not govern (G15): the worker checks it as *Composition* says, every name it writes free of other lines, and refuses a text that would not read where it lands as that one mapping line.

**G9, G12, G13, G15, G16, G22 — the document changes one line at a time, never silently.** By construction: only the worker writes `mappings` (R1), one operation at a time; each re-reads the document, checks its expectation (base equality, anchor found once and a mapping line, heading found, names free, document empty), and writes once. The line editor splices the original line strings and re-joins them with their own endings (R3), so untouched lines are byte-identical; a Vitest check compares every other line byte for byte. An unreadable line is never a valid anchor and is skipped by search; only *replace* can change it (G16). Failure direction: a lost race is a `stale` reply with the stored text, and the surface reloads and offers *Edit again*; a failed `set` leaves the old document (S1). Limit: E2.

**G10 — "This page is …".** The popup compares the opener tab's URL with each mapping's URL by string equality; with several, it names the first in document order.

**G17, G18, G20, G21 — the Text view.** Save validates the textarea's value with the document module, makes the textarea read-only, and sends *replace* with the base; the worker's base check is what prevents overwriting (G18 by construction). On `changed`, the view runs the module's three-way merge of base, the submitted text, and the stored text: lines are paired by a longest-common-subsequence diff of each side against the base and compared by content without line endings; stored-side changes in regions the submitted text left alone are applied with one action; a change both sides made alike (a region whose two versions hold the same lines, or lines both sides inserted at the same gap that the same diff, run between the two insertions, pairs) is applied once; other lines both sides inserted at the same gap are independent additions and both are kept, the stored document's first, unless two of them share a name (F4), which makes them a conflict; any other region where both sides changed or removed the same base lines, and every conflict, shows both versions for the user's choice; after merging, the base becomes the stored text it merged and the textarea is editable again, so the next Save's base check passes unless the document changed again (its validation still applies). A textarea reads CRLF back as LF (S14), and G17 stores what the textarea holds: a document with CRLF endings (1.x stored one when a CRLF file was imported and saved unedited) is stored with LF endings by its first Text view Save, as 1.x also did on any edit, while single-line changes keep its endings (G12). Import sets only the draft (G20).

**G19 — one draft, kept.** The `draft` key as in State, written only by the worker (R1), so a newer draft from another Text view is removed by a Save only when the document then holds its text, and never by another view's discard: removal on *replace* is conditional on text equality, removal on *draft discard* on the identifier and number of the edit it names, and both are serialized with every *draft set*. A draft found equal to the stored document when a Text view opens is dropped without asking. The quota is never reached inside E3 (State's budget).

**G23, G24, G25 — the upgrade changes nothing the user did not ask for.** `onInstalled` is the only code that reads `previousVersion` (R5); on an update it writes `upgradeNotice` and nothing else, and no install path ever writes `mappings` or `themePref`. Command identifiers are 1.x's, so Chrome keeps the user's reassignments (S12). The manifest changes (name, version, `contextMenus`, `omnibox`, a third command) carry no permission warning (S3) by construction of the manifest, and R8 keeps it so. Limit: Chrome closing in the instant before the install write lands, which E9 places outside the envelope; the absence defaults in State then leave a new install in Document order or an upgrader without the notice, never an upgrader in Smart order.

**G27 — the use score.** score = Σ over the entry's kept times of 2^(−age in days ÷ 7); equal scores order by line number. One use within the last 24 hours scores at least 2^(−1/7) ≈ 0.906; ten uses all older than 30 days score at most 10 × 2^(−30/7) ≈ 0.513; so the 24-hour/30-day clause holds given the ten-use cap. The key includes name and URL, so a rename or a new URL starts afresh, and the pruning after every write (Composition) keeps a former key's learning from returning. The popup reads `searchOrder` when it opens and on `onChanged`.

**G28 — the address bar.** The worker takes the list without group (f), which belongs to the popup alone (N4): row 1 is the default suggestion, set before rows 2 onward, at most 1,000 of them, go to `suggest` (S7), more than Chrome shows; with no row, the default says that no mapping matches, or, with nothing typed, asks for a mapping's name. A listed mapping row's `content` is the mapping's name; the listed argument row's `content` is its filled URL; a row whose content, after later Chrome's sanitizing (S7) and a trim, would be empty or equal the typed text or an earlier row's content gets ` (line N)` appended, N being its line number, then ` 2`, ` 3`, and so on until it differs from every other content and the typed text. Contents are thus unique and never merge with the default (S7). Before calling `suggest` the worker writes `omnibox` (State), so resolution survives its own restart (S2). On `onInputEntered`, the text and the stored typed text both after later Chrome's sanitizing (S7) and a trim: equal opens the stored row 1 (the default accepted); else equal to the content rebuilt for a stored row, compared the same way, opens that row; else row 1 of the list for the text; nothing, or empty text, opens nothing, and empty text lists nothing. A stored row opens with the name and URL stored for it, so a document changed since the list was shown still opens what was shown. `currentTab` maps to `tabs.update` on the active tab; both new-tab dispositions map to `tabs.create`, active or not accordingly.

**G29 — the menu.** On a click the worker writes `openIntent` and calls `chrome.action.openPopup({windowId})` for the click's window. If Chrome rejects because the window is not active, the worker keeps the intent and calls again when `windows.onFocusChanged` next names that window within the intent's 10 seconds; any other rejection removes the intent and nothing opens. Limits: S4's windows without a toolbar, which G29's own words exclude; and focus that leaves the window and stays away longer than that, which puts the popup in the state E4 admits for any loss of focus.

**G31, G33 — copying and no network.** Clipboard writes happen in the page under the user's gesture (S14). No network by construction: the CSP blocks every fetch, socket, image, style, and font from any origin but the package (S9); navigation to a mapping's URL is the user's own request and the only thing that leaves the machine.

**G32 — everyone.** By discipline (R7): every color is a token in one stylesheet, so the 4.5:1 check runs on that file; every control has an accessible name and a visible focus style; every flow has a keyboard path. Checked by review and by an accessibility pass inside the end-to-end checks.

## Substrate assumptions

The arrangements above hold inside the product's operating envelope and these assumptions; outside either, nothing is promised. Chromium sources are at tag 127.0.6533.72 or commit 470aafad67f9 (main, 2026-10-17); documentation is developer.chrome.com, read 2026-10-17.

- **S1.** A `chrome.storage.local.set` of one or more keys is applied as one LevelDB write batch, so when Chrome exits mid-write the keys hold the old or the new whole values together; the storage operations of one extension run on one sequence in arrival order, and one not yet started at shutdown is dropped; a set that would exceed the 10,485,760-byte quota, counted on the JSON serialization of values plus key lengths, is rejected before anything is written; a stored string reads back with U+FFFD in place of each lone surrogate and every other character as written, which E3 places outside the envelope. (`leveldb_value_store.cc`, `storage_frontend.cc`, `extension_file_task_runner.cc`, `settings_storage_quota_enforcer.cc`; LevelDB 1.23 `doc/index.md`, "Atomic Updates"; probe: 30 of 30 SIGKILL trials whole on Chromium 153; probe on Chromium 156, 2026-10-19: a lone high or low surrogate read back as U+FFFD, and NUL, U+FEFF, U+2028, and a surrogate pair as written.)
- **S2.** Chrome runs one extension service worker per extension in spanning mode, ends it after 30 seconds without events or API calls, resets that timer on each, and terminates a single request that runs over five minutes; its memory does not survive. (service-workers/lifecycle; blog/longer-esw-lifetimes; manifest/incognito.)
- **S3.** `storage`, `activeTab`, and `contextMenus` show no permission warning; `clipboardWrite` shows "Modify data you copy and paste", accepted at the 1.x install; `commands`, `omnibox`, `name`, and `version` are not permissions and warn for nothing. (permissions-list; permission-warnings.)
- **S4.** `chrome.action.openPopup({windowId})` is available to every extension from Chrome 127 and rejects for an inactive window, a window without a toolbar, or an already open popup. (api/action; `extension_action_api.cc`.)
- **S5.** Clicking the action, running a command, clicking the extension's menu item, or accepting its omnibox suggestion grants that tab's `url` and `title` to `tabs.query` without the `tabs` permission. (concepts/activeTab; `active_tab_permission_granter.cc`, `extension_tab_util.cc`.)
- **S6.** An action popup is clamped between 25×25 and 800×600 device-independent pixels; beyond that its viewport is clamped and scrolls. (api/action#popup; `extension_popup.cc`, `frame_view_auto_size_info.cc`.)
- **S7.** `omnibox.onInputEntered` receives the chosen suggestion's `content`, or the typed text when the default is accepted; `disposition` is `currentTab`, `newForegroundTab`, or `newBackgroundTab`; descriptions are XML with `<match>`, `<dim>`, `<url>`, parsed as XML 1.0, and one that is not well formed refuses the whole `suggest` or `setDefaultSuggestion` call; Chrome writes the typed text in place of the first `%s` of the default suggestion's description; Chrome 127 passes a content unchanged, later Chrome (470aafad67f9) trims its surrounding whitespace (base's `kWhitespaceUTF16`, which holds U+0085 and not U+FEFF) and removes tabs, line breaks, U+2028, and U+2029 from it, and ignores a default suggestion set after `suggest` for the same input; Chrome ranks suggestion i (from 0) at the default's relevance, at least 1,100 for a typed keyword, less i + 1, ranks one that would fall below 0 with the default, and shows at most 10 on desktop; Chrome merges suggestions whose content, so treated, is identical or equals the typed text. (api/omnibox; `omnibox_api.cc` and `keyword_extensions_delegate_impl.cc` at 127.0.6533.72 and 470aafad67f9, `keyword_provider.cc`, `autocomplete_input.cc`, `autocomplete_result.cc`.)
- **S8.** `tabs.create`, `tabs.update`, `tabs.query({active, currentWindow})`, and `windows.onFocusChanged` need no permission; from the popup, `currentWindow` is the popup's window. (api/tabs; api/windows.)
- **S9.** `content_security_policy.extension_pages` governs the pages and the service worker and accepts `default-src 'self'`, which is the fallback for every fetch directive. (manifest/content-security-policy; migrate/improve-security; W3C CSP3.)
- **S10.** `storage.onChanged` is delivered to every registered listener of the extension, the writer's own context included. (`storage_frontend.cc`, `event_router.cc`.)
- **S11.** The Web Store neither installs nor auto-updates an extension on a Chrome older than its `minimum_chrome_version`. (manifest/minimum-chrome-version.)
- **S12.** At most four commands carry suggested keys; a suggested key that is one of Chrome's own shortcuts on the platform is not assigned, and at 470aafad67f9 Alt+Shift+N is one on Windows and Linux (`accelerator_table.cc` `kLinuxAndWinAcceleratorMap`, `IDC_NEW_SPLIT_TAB`; `CanAutoAssign`); a shortcut the user reassigned is kept across an update for the same command identifier. (api/commands; `command_service.cc`.)
- **S13.** Menu items an extension creates persist across worker restarts, and across Chrome restarts once Chrome has stored them, which it does one second after the last change, so a Chrome closed within that second starts without them; the `page` context matches a right-click on the page itself but not on a link, selection, field, or media; the `link` context matches links and supplies `linkUrl` and `pageUrl`. (api/contextMenus; `context_menu_helpers.cc`; `menu_manager.cc` at 127.0.6533.72 and 470aafad67f9.)
- **S14.** `encodeURIComponent` leaves exactly `A–Z a–z 0–9 - _ . ! ~ * ' ( )` unescaped and throws URIError on a lone surrogate; a textarea's `.value` has CRLF and CR normalized to LF; `Blob.text()` is UTF-8 decode, dropping a leading byte-order mark and replacing invalid bytes with U+FFFD; `navigator.clipboard.writeText` needs a secure, focused document and a user gesture. (ECMA-262 §Encode; HTML §textarea; File API §text(); Encoding §UTF-8 decode; Clipboard API.)

## Standing rules

- **R1.** Only the service worker writes `mappings`, `usage`, `draft`, and `omnibox`, through the serialized operations of Composition, and `mappings` never without `usage` in the same `set`; no page calls `storage.set` or `storage.remove` for them.
- **R2.** Every rule about the document's text (parsing, validation, formatting, editing, search, score, substitution, merge) has its one home in the document module; no part reimplements or special-cases one.
- **R3.** The line editor splices original line strings and never reserializes an untouched line; an operation never targets a line that is not a mapping line.
- **R4.** A jump is sent only from an Enter handler or a row click handler; no other event, timer, or focus change opens a URL.
- **R5.** `runtime.onInstalled` is the only reader of `previousVersion`; on an update it writes `upgradeNotice` and nothing else, and no install path ever writes `mappings` or `themePref`.
- **R6.** The CSP stays `default-src 'self'`; no code calls `fetch`, `XMLHttpRequest`, or `WebSocket`, and no stylesheet or script loads anything from outside the package: no `src`, `href`, `import`, or `url()` in them names a URL outside it, while a URL held only as text (F11's example document, a mapping's URL, an XML namespace name, a link inside an error message) loads nothing.
- **R7.** Every color is a token in the one theme stylesheet; every interactive element has an accessible name and a visible focus style; every string is English.
- **R8.** The manifest's `permissions`, `commands`, and `omnibox` keys change only through an amendment of F5 to F8; no optional or host permission is ever added.

## Product decisions settled here

- **P1** (L4). Ctrl+E edits the selected row in the popup on every platform: it reaches the popup before Chrome acts on it on Windows and Linux and is unbound in Chrome on macOS (`accelerator_table.cc`, `extension_view_views.cc` at 470aafad67f9). Delete has no key.
- **P2** (L5). The Section choice shows a heading as the comment text of its lines, without the backslashes and surrounding whitespace, joined by single spaces, a line with no such text adding nothing; a heading with no such text on any line is shown by the number of its first line. The what's-new page holds the five items listed in Composition. The storage keys are those of State.
- **P3** (L3). The use score and its storage are those of G27 and State: ten kept use times per mapping, a seven-day half-life, keyed by lowercased name and URL, with a creation counted as a use for any write that brings a new key into the document.

## Left open

- **T1** (L6). Whether the List view renders every line or windows its rows is the implementer's decision from a measurement on a 10,000-line document. Rendering every line, with a row's editing controls created only while that row is edited, is the compliant fallback and stands unless the full view takes over one second to appear on the build machine; a windowed view keeps every row reachable by keyboard and pointer (G32).
- **T2.** How the upgrade acceptance of *Done when* obtains a 1.3.0 build is the implementer's choice (the project's history or the published package), under L1: no 1.x code enters the 2.0 source tree.
- **T3.** Closed 2026-10-18. Chrome exiting in the instant between installing and the worker's first storage write (S1 drops a write not yet started) left G24 and G25 unkeepable, since only `onInstalled` tells an install from an update; E9 now places that instant outside the envelope, and the G23 to G25 entry states the limit.
- **T4.** Closed 2026-10-18. Four copies of the document plus usage times could exceed S1's quota under E3's former "1 MB of text"; E3 now measures the document as Chrome stores it, and State's budget fits by construction.
